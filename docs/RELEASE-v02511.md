# 星枢 0.25.11：断报恢复与代理稳定性

主机有心跳不代表流量采样和节点应用都正常。此版分别检查它们，保留既有身份、节点凭据、套餐累计和手动地址。

- 主机样本超过控制端时间一分钟时明确提示双方启用 NTP，继续拒绝异常时间样本；没有放宽计费校验。
- 系统网卡采样独立于代理基线、内核验证和升级运行，运行循环初始化失败后自动重试。
- 控制地址修复先验证控制端身份和时钟，随后检查心跳、流量及所有启用节点的实际版本回报。健康主机的相同地址不重复重启；未恢复时返回具体检查项，不再只输出“地址已修复”。
- 跳跃端口占用只暂停对应 UDP 重定向，不阻止主监听或同内核其他入站。仍不接管其他程序端口、不修改已有防火墙放行策略；需排除占用端口并刷新订阅后恢复跳跃。
- 相同证书检查不重复下发节点；仅版本号、分享地址或客户端参数变化而原生配置与内核文件未变时，确认新版本并保留运行进程和现有会话。身份、权限、监听及实际原生配置变化仍正常应用。
- 主机页区分心跳在线与流量断报，Agent 日志显示端口预检或校时失败原因。

控制面兼容 0.25.9 / 0.25.10 Agent；独立采样、跳跃冲突隔离和配置免重启需要升级 Agent 至 0.25.11。升级 Agent 会有一次受控的托管内核重启。

运维时应在控制端和 VPS 都启用持续校时：`timedatectl show -p NTP -p NTPSynchronized`。没有校时服务的 Debian 主机可安装并启用 `systemd-timesyncd`；安装后必要时重启 `systemd-timedated` 刷新其服务列表，再执行 `timedatectl set-ntp true`。不要手动重置流量账本来消除断报警告。

验证包含 Go / API / 前端回归、独立 CA 子进程证书检查、真实内核进程保持验证、IPv4 / IPv6 跳跃与四平台兼容，以及发布后的全新安装、接入、恢复状态、升级和卸载流程。正式附件只有在这些发布门禁通过后才会标记为最新稳定版。
