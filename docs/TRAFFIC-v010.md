# 0.10 流量、额度与访问元数据

以 Remnawave 的用户额度 / 内部分组、2s-ui 的协议 / 流量界面为产品参考，独立实现；未复制它们的源码。参考：https://docs.rw/learn-en/users/ 、https://github.com/shenaba/2s-ui 。

## 计量口径

上传 + 下载计入本期额度；0 为无限，GiB = 1024³ 字节。按用户、主机、内核维护稳定绝对计数器；持久化 Agent 本地账本，启动先恢复控制端基线，重试与乱序旧快照不重复计费。日 / 月重置以北京时间自然日 / 月为边界，重置本期用量而非累计历史。手动重置有审计。

sing-box 使用官方私有 API 的用户连接事件；Xray 使用 StatsService 用户 email / 入站计数，均仅在动态回环端口监听，sing-box 使用随机认证密钥，Xray 仅启用读统计服务。连接数据直接解析，原始日志不写入增长文件。Agent 不链接完整代理内核，因此额外内存取决于连接数和有界计量表。

独立用户认证支持 VLESS、VMess、Trojan、Hysteria2、TUIC、AnyTLS。Snell / 当前 Shadowsocks 模板使用共享密钥，入口总量可统计，无法可靠拆分给用户。FRP 流量没有纳入本版计费统计。

首页入口用量与用户账单分别汇总，不能相加。链式代理每一跳分别产生入口流量；各入口合计表示逐跳消耗。用户账单依据实际认证身份计量。流量从升级开始，无法追溯历史。

## 额度执行

只有 Agent >= 0.10 的主机允许为用户设置正数额度。内核计量连续正常才下发有限额用户；计量不可用超过 30 秒则该主机有限额身份在下次同步被移除。上报跨过额度时更新受影响入站版本，Agent 下次同步删除身份并重启该内核的合并进程，关闭旧连接。

约 10 秒上报与对账，存在短时超额。异常退出、内核计数窗口和损坏账本不能保证电信计费级精度。本地账本出错拒绝启动，不静默清零；控制面不可用超过 90 秒停止所管服务。不能用作承诺零超额的商业计费系统。

## 访问记录

记录连接建立时观察到的来源 IPv4 / IPv6、目标域名或 IP、目标端口、TCP / UDP、入口和已识别用户。HTTPS 页面内容和完整 URL 不采集，域名可能缺失而显示目标 IP。经中继 / NAT 时来源可能是出口或上一跳地址，不能伪称原始设备 IP。

每次上报最多 100 条；事件不构成完整浏览历史。最多保留 7 天 / 20,000 条，页面最近 200 条，可按用户筛选；日流量汇总 90 天，用户累计数字保留至删除用户。仅管理员可查询，不进入公开订阅。

## 清理与资源

旧入口在 Settings 的清理页预览。仅停用且 Acceptance 前缀的旧验收配置可清理，真实用户组、普通订阅、未选择的链路 / FRP 引用会阻止清理。当前版本停止确认后才能释放端口。真实运行配置不作为试用数据删除。

主页按 30 秒刷新，后台标签页暂停；图表不引入绘图库。计量每主机最多 2,000 个紧凑计数器、100 个待报访问事件；sing-box 连接跟踪最多 20,000 条，超限报告计量不可用。库连接池与服务资源上限沿用部署限制。

验证覆盖：真实双内核转发 / 用量 / 来源和目标、账本重启 / 基线恢复、上报重试去重、超额移除身份、手动 / 日重置、IPv6 记录、无权限和非法目标拒绝、清理范围保护。运行记录见部署交付说明。

在线 / 计量新鲜度及订阅有效期由控制端数据库时钟判断，避免客户端时钟偏差误判。
