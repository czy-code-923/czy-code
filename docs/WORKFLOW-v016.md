# 0.16 订阅检查与节点成员

分享前调用 `GET /api/v1/subscriptions/{id}/check?client=mihomo`，使用真实订阅编译流程检查授权、节点部署、兼容性、策略和额度。返回 `ready/stage/status/reason`，不返回私密链接或代理凭据。检查通过不代替客户端本机合并配置及网络连接测试。API 权限为 `subscriptions:read`。

分享窗口默认显式选择 Mihomo，支持切换客户端。检查失败时禁止复制，显示可操作的原因；切换格式重新检查，旧检查结果不覆盖新结果。停止的节点不发布，空订阅保持 HTTP 503；不会用空 YAML 伪装成功。

格式优先级：链接显式 `client`、`format` → 已识别客户端 User-Agent → 关联输出预设 → sing-box 默认。自动识别和显式选择都筛除不兼容节点；全部不兼容返回 422。客户端原生覆盖只在对应格式应用。

新策略组默认选择 `ALL`，动态包含订阅用户获授权且运行、兼容的全部节点。手动模式按稳定 `node:<id>` 勾选，重名节点不会混淆；一个节点的多个入口地址均保留。其他组、直连和按协议/地址族的动态引用单独收起，成员顺序决定默认项。内置模板根节点组加入 ALL，已保存策略不会被升级覆盖。

导入 YAML / JSON 读取节点协议、地址和端口，仅做唯一端点匹配；同端点多节点时可用唯一名称区分。没有端点的别名必须唯一匹配名称与协议。歧义或端点不符时要求手动映射，不再自动扩大为整个协议。导入不保存原始身份凭据。

本版不需要新增数据库迁移。现有节点、用户、策略、订阅链接及 Telegram 设置保留。升级前备份数据库及配置，使用对应平台分发包；现有服务器更新包先在隔离数据库运行 API 测试再替换程序，健康检查失败时回滚程序。
