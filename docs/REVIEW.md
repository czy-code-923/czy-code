# v0.1 复查与 v0.2 修复

整体架构合理：模块化单体控制面 + PostgreSQL + 每主机主动连接 Agent，实例作为主机和节点的关联，适合当前规模。复查发现以下实际逻辑缺口，已修复并加入回归验证，不能把原来的基础测试通过等同于所有功能都正确。

|问题|影响|本次修复与验证|
|---|---|---|
|跨表端口检查缺失|FRP remote_port 可撞本机其他实例监听口，两个 FRP 实例也可抢同端口|统一 port_reservations 主键；业务与预留同事务；测试两类冲突及失败回滚|
|旧 Agent 只检查部分清单字段|错误/越界/重复隧道端口或非回环本地目标可能被误报模拟成功|共享类型化 manifest 校验与摘要验证；测试嵌套目标、端口、引擎及额外字段|
|任务过期只在主机重新领取时检查|离线主机已耗尽的任务长期 running|独立定时回收器；使用数据库锁回收，可重排或终结；测试无需主机请求即可回收|
|重复完成回报直接冲突|响应丢失时 Agent 无法判断已完成回报能否重试|保留完成租约证明；相同结果/摘要回报幂等；不同结果拒绝|
|资源输入使用所有类型的字段并集|属于其他资源的字段会被静默忽略，与 OpenAPI 不一致|每种资源字段允许列表；测试无关字段返回 400|
|中转 ID 数组无关系外键|未来删资源会留下悬空 hop|新增有序 route_hops 关系表，与数组在同事务写入及迁移回填|
|FRP 快照未固定排序|相同隧道集合可能生成不同摘要|按 remote_port/id 排序再生成快照|
|刷新覆盖操作错误|请求失败信息下一次轮询就消失|操作错误与同步错误分离；前端实际组件回归测试|
|退出后未完成请求可能回填界面或一次性凭据|用户已退出但页面重新显示后台数据|会话版本校验 + 中止旧请求；测试延迟轮询及延迟凭据响应|
|移动端退出入口被侧栏样式隐藏|窄屏不能正常主动退出|顶部常驻退出按钮；浏览器窄屏检查|
|阶段扩展的锁顺序风险|入队锁实例，完成若先锁任务再锁实例会产生死锁循环|所有需要双重锁的入队/完成操作统一实例→任务顺序；并发队列及真实数据库验证|

v0.2 增加原生预览、固定引擎校验、私有文件暂存、摘要记录、历史成功版本回退和租约续期。原生程序仅执行 check / verify；新增功能不把“暂存成功”当作“服务已运行”。

数据库升级测试还验证：旧数据存在端口冲突时，003 迁移完整回滚，不残留新表或迁移记录；修复冲突后可重新升级并正确回填端口预留。

## 仍保留的明确边界

未提供真正多租户账号/RBAC、mTLS、引擎安装/运行、Linux systemd 和防火墙管理、跨机 FRP 拓扑、真实中转编译、计费/订阅、全量 CRUD、分页或生产容灾。数据库管理身份可修改数据，私有状态也不防御同账号或更高权限的本地攻击者。后续方向见 ROADMAP，当前交付不等于完整商用平台。
