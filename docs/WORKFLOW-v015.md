# 星枢 0.15：查询、通知与统计

通知发送、长轮询接收、Telegram 命令菜单分别配置和显示。私聊可显式填入已绑定聊天的用户 ID；群聊仍需逐个授权查询用户。测试发送不会掩盖接收异常，诊断不会调用 getUpdates 或删除 Webhook。命令菜单仅同步绑定聊天范围，且使用已保存的命令授权。

长轮询使用 Telegram 响应的 Date 判断命令时间，避免 VPS 时间偏差误拒绝合法命令；缺失 Date 时回退到本机时钟并容忍有限偏差。过期消息丢弃、消费游标先持久化，防止重放。每轮最多取 3 条，不再取 10 条后静默丢弃超额回复。命令 /start 对应已授权的 /help。存在冲突或限流时退避；接收故障不会阻止定时报告与事件发送。通知是尽力投递，网络失败可能重复或遗漏；不保证交易级投递。

客户端策略是基础、DNS、策略组、规则的唯一常规编辑入口。桌面等宽双列、同高列表，各自滚动；手机切换列表。订阅分享只管理链接和用户。已有 client_profiles 输出预设保留，集中在策略页高级区域维护，最后覆盖顺序不变。未静默删除或迁移生产配置。

首页：今日入口总量按北京时间和链路逐跳计量；用户本期已用按各自重置周期求和。有限剩余额度逐用户 max(分配-已用,0) 后求和，无限用户不会扣减此余额。近 60 秒活跃用户只包含当下有效且未耗尽额度的用户。14 天趋势补齐零日期；指定用户页使用该用户的日序列，不混用全局入口总量。

访问记录默认收起，展开才请求最近 50 条。页面不可见时停止周期请求，卸载时取消定时器。API 保留原默认最多 200 条，并支持 limit=1..200。首页不包含 HTTPS 页面内容或完整 URL。

新增 POST /api/v1/notifications/telegram/diagnose 与 /commands；notifications:write 权限。GET /notifications/telegram 返回独立 health。GET /dashboard 可携带 user_id 获取该用户日序列，全局库存汇总字段仍为全局；前端按页面范围选取字段。
