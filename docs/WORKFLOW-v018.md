# 0.18 主机套餐、用户计费与设备权限

主机 → 内核 / 入站 → 用户与用户组 → 客户端策略 → 设备专属订阅。0.17 的端点选择、官方内核切换、FRP 与用户 CRUD 保留。

## 主机流量

添加或编辑主机时设置套餐字节数、计量方式、每月重置日和自动重置开关。0 表示不限额。页面可选择 GB（10⁹）或 GiB（2³⁰）；API 一律为整数字节。

Agent 0.18 每约 10 秒读取 Linux / Windows 系统网卡累计 RX / TX，持久化游标后主动回报。默认选择系统默认路由的上联网卡，排除回环、Docker/veth、TUN/TAP；多网卡可以手动选择。不要同时选择同一链路的物理口和桥接口，否则可能重复统计。主机计量包含更新下载、SSH 等代理之外的系统网络流量，不应等同于用户代理账单。

双向 = 周期累计 RX + TX；仅入站 = RX；仅出站 = TX；取较大值 = max(本周期累计 RX, 本周期累计 TX)，不是逐轮较大值相加。界面展示余额、两方向累计、近次速率、采样时间、下次重置时间和计量质量。最多约 10 秒上报延迟，超过 35 秒标为断报；前端当前页面约 30 秒刷新。余额是最近有效采样的结果。

已有主机首次升级不可能还原服务商本账期的历史用量。请在“主机套餐流量 → 校准”输入服务商同一时刻已用量；之后只累计新流量。账期、GB/GiB、服务商协议头口径可能与操作系统不同，不能保证天然与账单逐字节一致。Agent 重启可恢复已保存游标；系统重启、网卡计数回退、账本丢失会标记缺口，校准后清除已确认缺口。无数据不能显示成可信的 0 或精确余额。

重置按 Asia/Shanghai 每月指定日 00:00 执行，例如 5 日 → 下个月 5 日；31 日遇小月取月末，下个月仍以 31 日为锚点。周期清零不会清除 OS 游标或重复计算旧流量。主机套餐目前用于统计与通知，达到上限不会自动中断整台主机；用户代理额度仍会撤销其独立身份。

## 用户流量

默认双向、1×。可选上传、下载或周期累计较大值，并设 0.001～100× 倍率；API 使用 multiplier_milli（1000 = 1×）。使用整数运算和周期累计差值避免每轮取整放大。用户原始上传 / 下载与计费后的已用量分别保存。修改倍率只影响之后的流量，已计费部分保留；修改重置日不会静默清除账单。Subscription-Userinfo 的 upload + download 等于计费已用量，Clash/Mihomo 可以读取实际计费余额。

## 设备与权限

用户和用户组都可以设置 max_devices，0 不额外限制，多个限制取最严格的非零值。实际资源上限：每用户最多 20 个启用身份、200 条历史登记；工作区最多 400 个启用设备 / 2000 条登记；单入站最多 500 个用户与设备身份。降低名额时必须先停用超出的设备，避免静默删除或越权。

启用设备上限后，通用用户身份从入站撤销，使用“用户 → 设备 → 登记设备”生成每设备独立订阅 / UUID / 密码。设备可单独停用、删除、选择客户端，跟随用户全部节点或手选已授权独立身份节点。手选空列表拒绝全部节点；设备权限始终与父用户权限取交集。删除节点清理引用，不会扩大授权。更改权限等待 Agent 应用回执，已建立连接可能在内核重新载入时断开。

普通 VLESS / VMess / Trojan 等协议无法可靠回传物理硬件 ID。这里限制独立设备凭据名额，不能识别同一凭据被复制后的真实物理设备数。UA 是订阅请求自报值，来源 IP 是代理连接的观测地址，NAT / IPv6 / VPN 都可能改变 IP。不能用 IP 数伪装成设备数。SS / Snell 共享密码没有逐用户设备限制，不进入设备专属订阅。

列表只返回设备名称、客户端自报、最近代理活动、最近来源 IP、累计原始用量和节点权限；设备密钥与订阅链接使用独立 devices:links 权限。轮换父用户凭据同步轮换子设备凭据；用户续期同步设备订阅期限。

## 连接元数据

只记录代理连接的时间、用户 / 设备 / 入站、来源 IP、目标域名 / IP、端口、网络类型，以及内核实际提供的连接字节。不记录 HTTPS 内容或完整 URL。每轮最多 100 条，待回报队列最多 2000；高并发不能保证审计每一条连接。数据库最多保留 7 天 / 20,000 条，定时清理。

首页展开后可分页查看全部保留记录（每页最多 200），按连接时间或连接字节升降序，支持用户 / 主机 / 设备和目标 / 来源过滤。区域可见且浏览器标签可见时每 30 秒刷新，收起、离开屏幕或后台标签暂停。sing-box 提供连接计数时展示实际值；Xray 日志没有分连接字节时显示“—”，不借用用户总量。

## API / Telegram

新增 GET/PUT /api/v1/hosts/{id}/traffic、POST .../traffic/calibrate；主机创建 / 修改支持 traffic 对象。更新与校准需要读取版本，陈旧版本返回 409。查看使用 usage:read，配置 hosts:write，校准 usage:reset。主机删除级联清理计量与游标，仍使用受控远程卸载流程。

新增 /api/v1/proxy-users/{id}/devices CRUD 与 /{device}/link；创建要求 devices:write + devices:links，列表 devices:read，编辑 / 删除 devices:write，恢复分享链接 devices:links。读权限不能得到 UUID、密码或链接。用户 CRUD 增加 billing_mode、multiplier_milli、max_devices，组权限增加 max_devices。连接分页为 GET /api/v1/access-records/page，权限 usage:read。完整参数见 [OpenAPI](openapi.json)。

Telegram 增加只读 /devices；/hosts 显示主机套餐余额与采样状态，/users 显示倍率，/traffic 区分代理原始量和计费量。设置可以选择 host_quota / device_limit 告警与 devices 定时报告。新增告警默认关闭，旧机器人绑定和命令授权保留；阈值触发与去重，不发送凭据、来源 IP、UA 或订阅链接。

## 升级与验证

控制面、前端和 Agent 同升 0.18；迁移 023 增量建立计量和设备数据，不清除节点、订阅与机器人配置。新装 Linux / Windows amd64、arm64 使用 README 的固定版本校验安装器。现有宝塔 /opt/harbor 布局可使用 starhub-v018-update.zip；通用安装不要运行此专用升级器，先备份数据库及私有环境，再按安装文档替换对应组件。

验证包括 PostgreSQL API、游标幂等、周期 max 与校准、倍率响应头、设备权限和撤销、分页、通知去重、真实 Windows 网卡计数、前端交互及 Linux / Windows 原生内核转发。发布流程另在全新 GitHub VM 实测一键安装、Agent 接入、官方内核切换、设备代理传输与受控卸载；独立 API 测试二进制在空目录运行，防止漏打包测试文件。
