# 0.17 工作流与升级

主机连接 → 内核与协议入站 → 用户组授权 → 客户端策略 → 分享订阅。协议、传输、安全层继续按内核能力校验。

## 精确到 IPv4 / IPv6 的策略成员

同一个双栈 `trojan` 入站仍只运行一个服务，但提供两个发布端点，策略编辑中显示 `trojan-v4` 与 `trojan-v6`。成员保存为 `endpoint:<节点ID>:ipv4` 或 `:ipv6`，不会因同 ID 展开另一地址族。旧的 `node:<ID>` 保留“整节点所有地址”语义，第一次取消其中一个复选框即转换为逐端点引用。手动选择替换 ALL / 地址族 / 协议 / 主机动态过滤；可保留其他策略组和 DIRECT。

“全部已授权节点”和地址族动态选择继续随实际节点变化。空模板不内置任何协议或固定节点；创建后才显示。删除节点或退役主机时，显式成员及导入映射会同步清理；空组改为 REJECT，不扩大到其他节点。引用已删除节点的直接规则改为 REJECT。已下载到客户端的旧配置需更新订阅才会反映变更。

PROXY 不再无条件插入。只有规则或成员明确引用它，或无任何策略组且缺少默认规则时才生成，并放在最后。最终配置仍可包含策略未选择的其他授权节点供其他组使用，但当前组只含选中的端点。

内置默认模板保留提供的 Mihomo Max 的 21 组和 186 条规则，移除固定协议占位。只有字节完全匹配旧内置模板、名称未改且没有节点映射的全局模板自动迁移；手动修改、改名、用户专用策略和已删除模板保留。

## 官方内核管理

主机 → 内核版本，可查询最新稳定版、更新最新或指定上游版本；sing-box 与 Xray 独立。需要控制面和 Agent 0.17。发行包固定为官方 sing-box v1.14.4、Xray v26.10.21、FRP v0.71.1；在线按钮实时解析上游 latest，再把精确标签排入任务，避免下载时版本漂移。

仅接受固定官方仓库的发行文件；核对上游 SHA-256、文件大小、二进制版本和当前配置。下载在独立工作线程执行，期间现有服务继续运行；验证后短暂重启所选内核的所有入站，失败回退。状态跨 Agent 重启保存；版本缓存保留最多三份且保护当前及最近回退版本。单主机同时只允许一个更新任务。没有自定义 URL、路径或 shell 执行接口。

官方二进制与自编修复版不同，本版不再用 Harbor 名称标注 sing-box。上游版本及其依赖可能仍有漏洞公告；来源和摘要验证不等同于无漏洞保证。已有主机升级 Agent 后，仍需在内核版本页面主动切换官方版本；不会静默替换正在运行的内核。

## FRP

公网可达主机运行 frps；NAT / 无公网 IPv4 的主机运行 frpc 并主动连接 frps。必须确保 frpc 能通过 IPv4 或 IPv6 到达服务器；双方都不可达时仍需第三台可达中继。仅提供受控 TCP / UDP 端口映射，目标限回环地址，管理端口禁止转发，服务端预留端口与客户端类型、端口必须匹配。控制连接固定 TLS 证书与 token。

frps 控制端口放行 TCP，映射端口按 TCP 或 UDP 放行；frpc 通常只需出站。UDP 需双方 Agent 0.17；降级后会拒绝启用并停止不兼容下发。界面“进程运行”表示进程健康，实际映射连通性还需从外部访问验证。尚未实现 FRP P2P / HTTP 虚拟主机等所有上游功能。

## 外部面板 API

见 [机场面板集成](API-INTEGRATIONS.md)。用户 CRUD、外部用户 ID、24 小时创建幂等、游标分页、并发版本、额度和按月指定日重置均可调用。用户与订阅密钥权限独立；内核更新使用单独 kernels:update。当前仍是一个 self 工作区，最多 500 用户；不是完整售卖、计费或终端用户登录系统。

## 升级与验证

新装使用 README 的 0.17 校验安装命令；自建系统先备份数据库和私有环境文件，再替换同版本控制面、前端与 Agent 并运行自动迁移。订阅地址和凭据保留。`starhub-v017-update.zip` 的 apply.py 只适用于既有 `/opt/harbor`、宝塔 Nginx、systemd 与 harbor-postgres 的部署布局，不能当作通用升级器。

自动验证包括 PostgreSQL 隔离模式 API、权限与幂等、逐端点策略、删除清理、官方内核真实 TCP/IPv6、FRP TCP/UDP、内核版本校验和切换、前端交互。GitHub 全新 Linux 安装还执行一次线上官方内核更新、真实入站与受控 Agent 卸载。Windows / Linux amd64、arm64 都构建发行包，Windows CI 执行本机内核转发；Windows 服务安装需自行满足 Docker Desktop 与登录任务前提。
