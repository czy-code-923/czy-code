# v0.3 资源优化与测量边界

目标是三台 VPS 的个人控制面，保留功能，减少空闲唤醒、重复传输及临时内存；没有为追求指标删除队列、版本、审计或安全验证。

|部分|改进|代价 / 可配置边界|
|---|---|---|
|页面数据|一次 snapshot 请求替代 8 个并行列表请求；配置正文按预览获取；真实总数独立聚合|一次网络/数据库往返仍包含多个 SQL 子查询，不等于只扫描一张表|
|刷新|默认节能：有活动任务15秒、空闲30秒；实时模式5/15秒；手动模式不轮询；后台完全暂停|用户可切换实时模式；页面显示可能延迟到下一次刷新|
|重复内容|ETag + 304，不重复传输/替换数据，兼容 gzip 代理的弱 ETag|服务端仍会查询以判定是否变化；不是免数据库请求的缓存|
|历史|列表 limit/offset；本页15条；默认载入最近200条，审计100条；更早记录按需载入，页面最多1000条|搜索只覆盖已载入记录；不是全库全文检索；API 可继续分页|
|Agent|心跳约30–45秒；空闲领取退避2/4/8/15秒；连接失败最长60秒退避；工作后1秒继续|空闲新任务领取最多约15秒；90秒心跳阈值仅表示连接新鲜度|
|数据库|默认最多4条池连接、最小0条、空闲2分钟释放；添加租约/时间索引|可通过连接 URL pool_max_conns/pool_min_conns 覆盖；大规模需按负载调优|
|摘要|整文件读取改为流式 SHA-256；仍每次核验可信二进制|没有通过省略摘要验证换性能|
|Web|自制 SVG/CSS，无图表/UI大库、网络字体或装饰视频；Nginx 单 worker、gzip、512连接|更高并发再调 worker/连接，不应盲目照搬小规模配置|
|Compose|API/Agent GOMEMLIMIT 128MiB；API/Agent 各192MiB、Web64MiB、DB384MiB上限；DB64MiB shared_buffers /30连接|上限不是实测用量；超限会被容器终止；本机未运行Docker，需在目标机观察RSS/延迟/队列|

## 实测摘要分配

2026-10-22，Windows amd64、Go1.27.3，在16MiB模拟二进制上运行：

```sh
go test ./internal/executor -run '^$' -bench BenchmarkBinaryDigest -benchmem
```

本次样本旧实现约 **16,788,716 B/op**、流式实现约 **33,448 B/op**，单操作分配减少约 **99.8%**。这不代表整个进程的 RSS 减少99.8%，也没有用一次冷热磁盘样本宣称 CPU/吞吐固定提升。

按刷新调度计算：旧版每分钟约80个请求（8列表/6秒）；节能模式空闲约2个、有任务约4个，分别减少97.5%/95%。这是调度推算，非负载压测结果；主题切换、手动刷新、页面首次加载和操作后刷新另计。

本次重新验证：前端12项回归、真实数据库集成、原生 sing-box/FRP 校验、Linux交叉编译和已有端到端流程。未进行Linux实际RSS/CPU压测、容器测试、网络高并发或真实三机流量测试。不要把容器限制当作最低配置承诺。

## v0.4 增量

域名与分享页仅打开时载入与轮询元数据，后台暂停；真实服务规范不进入库存快照，分享凭据按需解密。真实Agent每10秒协调，不重写未改变的配置；错误退避、离线90秒停止受管进程。域名同步每分钟检查，未改变的配置/证书不重载，证书检查12小时一次，失败30分钟退避。

原生控制面直接提供已构建的静态前端，无Node常驻。Linux普通Agent的MemoryMax覆盖其受管子进程，实际需要按节点数/流量调整。新增真实引擎的占用不包含在v0.3单个控制面RSS样本内，不能宣称整台VPS或整套软件只占该数值。
