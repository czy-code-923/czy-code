# 星枢 0.23.12

保留现有主机、协议、用户、计量、策略与订阅功能，完善域名变更恢复、数据库资源和移动端显示。

- 设置可保存独立 Agent HTTPS 控制地址（最多 4 个）。新版 Agent 从已鉴权心跳获得候选地址；先验证绑定目标地址和随机挑战的 HMAC 证明，再发送令牌。拒绝跳转、明文降级及未配置地址的证明请求。保存可验证的恢复地址，切换失败保留当前入口；不重放结果不确定的任务请求。
- 主机卡片显示 Agent 实际控制地址。连接向导提供摘要固定的地址修复命令，保留 HOST_ID、令牌、内核与流量账本；另提供标准 Linux Agent 升级命令，验证同版本 GitHub 正式包、摘要和二进制版本，启动失败恢复旧程序。
- 更新助手按物理内存将旧的小额数据库限制扩大到 256 / 384 / 512 MiB，保留更大或不限额设置与现有更宽的 swap 设置，不重启数据库。新安装和 Compose 默认上限 512 MiB，可配置。后台版本页展示最近资源回报。
- 更新助手拒绝同时含公网映射的数据库容器；只有验证安装归属、环境文件和本地数据库之后才可操作。管理更新仍限本地助手和主管理员，正式包 SHA-256、数据库备份、健康检查和失败回退保留。
- 手机导航改为三列，修复首页按钮与品牌重叠；长地址、设置行、命令、弹窗和操作按钮支持窄屏，触控目标至少 44px，输入字号避免手机自动放大。保持桌面布局和按需加载页面。
- OpenAPI 同步增加验证与修复接口、Agent 地址、心跳和数据库资源字段；修复命令权限为 `hosts:enroll`。

## 升级顺序与限制

1. 主管理员进入「系统设置 → 后台版本 → 检查更新 → 更新到 0.23.12」。本地更新助手需显示“已就绪”。正式版发布前不会提供升级。
2. 控制面升级后刷新网页，在「连接主机 → 连接 / 恢复」为远端标准 Linux 安装生成 Agent 升级命令，并在原主机 SSH 执行。旧 Agent 保持兼容，但自动地址迁移需要 0.23.12+。
3. 地址变化时先准备有效 HTTPS 反代，保留旧入口至所有主机完成心跳切换；若旧入口已失效则使用地址修复命令。独立 Agent 地址不会自动生成第三个 Nginx 网关。离线主机不能由网页凭空恢复网络或启动已停止的服务。

更新不切换现有 sing-box / Xray / FRP 版本，不更改 Cloudflare，不卸载宝塔 Nginx，不清理生产数据。更新和 Agent 重启可能短暂中断本机服务。Windows / Compose 的面板更新仍遵循手动流程；远端升级命令仅支持现有标准 Linux systemd Agent。

候选版 0.23.10 因安装验收脚本写死旧版本号而未提升为正式版。本版改为从源码读取预期版本，分别核验实际控制端和 Agent，避免后续更新重复触发陈旧断言；重新构建并验证完整发行包。

## 容量与验证

512 MiB 是按需使用的数据库上限，不是预占。几十台主机与上百用户需要结合实际请求量、计量采样、磁盘、连接池等待和峰值压力验证，不能仅凭用户数量承诺容量。此版维持默认 4 条应用数据库连接和有限元数据保留，不提高采样频率。

发布工作流执行 PostgreSQL 集成、Go 竞态与静态检查、前端测试和生产构建、Python 安装/回退/资源/地址证明测试；构建四平台包，完成 Linux 新装、Agent 注册和卸载验收后才提升为正式版。生产环境升级结果须另行确认。

生产环境验证补充：修复 / 升级脚本使用明确的 `Starhub-Agent-Repair` User-Agent，避免 Cloudflare Browser Integrity Check 将默认 Python urllib 标识拒绝为 1010。保持 HMAC 身份验证、HTTPS 与摘要固定，不关闭网站防护。
